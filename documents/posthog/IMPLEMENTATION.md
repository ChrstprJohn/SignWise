# How SignWise analytics is built

## Initialization

`src/main.jsx` imports `src/analytics.js` before rendering React. That module initializes `posthog-js` when `VITE_POSTHOG_TOKEN` exists. The host defaults to US ingestion; override it together with the corresponding project's public token for another region.

The SDK captures initial pageviews and history changes through `capture_pageview: history_change`. This covers both full-page links and SignWise's custom `history.pushState` navigation. No second manual pageview capture is added. Click autocapture is enabled, with all DOM text and element attributes masked and copied-text capture disabled.

`loaded` registers `site_name = signwise` and the Vite mode as `environment`. `before_send` enforces those properties on automatic and custom events. `trackEvent` also attaches them, respects PostHog capture opt-out, and catches analytics failures. Profiles use `identified_only`; SignWise does not call `identify` or send names/emails. Anonymous distinct IDs still allow visitor/funnel analysis and are not a count of known individuals.

Session recording, automatic exceptions, performance capture, and surveys are explicitly disabled. Do not enable replay on document-review pages without a separate privacy review. Normal browser metadata (including URLs/referrers and device information) is still processed by the SDK; never put document content or private values in URLs.

## Safe metadata

`src/analytics-metadata.js` builds controlled metadata rather than passing File objects or report objects into PostHog:

- `file_type`: `pdf`, `docx`, `txt`, `jpeg`, `png`, `webp`, or `other`; JPG is normalized to JPEG.
- `file_size_bytes`: a nonnegative byte count.
- `context_provided`: a boolean, never the note itself.
- `red_flag_count`, `good_term_count`, `question_count`: array lengths, never findings or questions.
- `duration_ms`: elapsed browser time for an analysis attempt, including network latency.

Filenames, document contents, document titles/types generated by AI, notes, quotes, currencies, extracted text, summaries, findings, provider error messages, and report-export contents are not sent as custom event properties. Numeric counts and sizes are still usage metadata. There is no GPS collection or geolocation prompt; approximate city/country relies on PostHog enrichment and can be missing or inaccurate.

## Event reference

All events include the site/environment tags above. Automatic events also contain the SDK's normal browser properties.

| Event | Trigger | Additional properties |
| --- | --- | --- |
| `$pageview` | Initial page load and history navigation | SDK URL/device/referrer metadata |
| `$autocapture` | DOM click | Masked interaction metadata |
| `review_started` | Home-page review CTA | `source`: `hero` or `closing_cta` |
| `review_upload_viewed` | Upload route becomes active | None |
| `document_selected` | Valid file/photo selected | File metadata; `source`: `file_picker`, `camera`, or `drop` |
| `document_selection_rejected` | Invalid selection | `source`, `reason`: `multiple_files` or `file_validation`; file metadata for single-file rejection |
| `document_removed` | Selected file removed | File metadata |
| `document_review_blocked` | Analyze fails client validation | File metadata; `reason`: `file_validation` |
| `document_review_started` | Explicit Analyze action starts an attempt | File metadata; `context_provided` |
| `document_review_succeeded` | Valid review response accepted | Attempt metadata; `duration_ms`; review counts |
| `document_review_failed` | Active attempt fails | Attempt metadata; `duration_ms`; `http_status` (0 if unavailable); `error_type`: `timeout`, `network`, `server_error`, or `invalid_response` |
| `document_review_cancelled` | Cancel or component cleanup ends an active attempt | Attempt metadata; `duration_ms`; `reason`: `user` or `navigation` |
| `review_results_viewed` | Results page mounts or its report changes | `report_available`; file/context metadata and review counts only when a report exists |
| `review_download_requested` | Save review clicked | File/context metadata; review counts |
| `review_download_started` | Browser export link activated | File/context metadata; review counts |
| `review_download_failed` | Export setup throws | File/context metadata; review counts; `error_type`: `export` |

`review_started` describes a CTA click, not an analysis attempt. Users arriving directly at `/review/` skip it. File selection does not upload the file; only Analyze sends it to the existing server/Gemini flow.

## Lifecycle and limitations

`App.jsx` and `ResultsPage.jsx` use refs to suppress duplicate effect events during React StrictMode checks. `ReviewPage.jsx` keeps each analysis attempt in a ref and marks it finished on its first terminal event. Existing job guards prevent cancelled or stale responses from becoming success events. Cancellation blocks the button's default action to prevent an accidental immediate resubmission.

Reports remain in React memory, with only safe attempt metadata attached for downstream analytics. No document/report persistence is introduced. Refreshing results emits `review_results_viewed` with `report_available = false`; exclude that from successful-results metrics. Component cleanup can record navigation cancellation, but abrupt tab closes/network loss are not guaranteed to deliver any event.

Download-start measures a browser export attempt, not proof that the user saved or opened the file. Attempt totals may exceed visitor totals because retries are counted separately. There is no review ID or server-side analytics delivery; user/session funnels are directional when someone reviews multiple files in one session. The existing API and Gemini key handling are unchanged.

## Source map

- `src/analytics.js`: SDK options, event tags, safe capture wrapper.
- `src/analytics-metadata.js` and its test: controlled file properties and counts.
- `src/main.jsx`: initialization import.
- `src/App.jsx`, `src/InfoPages.jsx`: entry CTAs and upload-route event.
- `src/ReviewPage.jsx`: selection and analysis attempt events.
- `src/ResultsPage.jsx`: results/recovery and export events.
- `.env.example`: browser configuration template. `.env.production` and `.env.local` are ignored local config; production hosts must supply build-time variables.

References: [PostHog JavaScript configuration](https://posthog.com/docs/libraries/js/config), [Vite environment variables](https://vite.dev/guide/env-and-mode).
